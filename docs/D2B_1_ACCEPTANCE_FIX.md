# D2B.1 — Lesson Acceptance Gate Fix

Визуально D2B принят. Техническая приёмка нашла **два** несоответствия; D2B.1 чинит только их.

Исходный HEAD: `5057017`.

---

## 1. Fix A — стандартный E2E gate был неполным

**Было:** `"test:e2e": "playwright test e2e/smoke.spec.ts"` — 21 из 116 обнаруженных тестов (18%).
Path и Lesson behavioral suites не запускались под стандартным gate вообще.

**Стало:**

| Скрипт | Значение | Охват |
|---|---|---|
| `test:e2e` | `playwright test smoke.spec.ts` | **78** behavioral в 5 файлах |
| `test:e2e:all` | `playwright test` | **121** — полный discovery |

Playwright трактует аргумент как **regex по пути файла**, поэтому `smoke.spec.ts` матчит
`smoke.spec.ts`, `path-smoke.spec.ts`, `path-r1-smoke.spec.ts`, `lesson-smoke.spec.ts`,
`lesson-session-smoke.spec.ts` — и не матчит ни один `*-screenshots.spec.ts`.

Это эквивалент предложенной схемы `e2e/smoke.spec.ts e2e/*-smoke.spec.ts`, но **надёжнее**: не зависит
от того, раскроет ли shell glob (в npm-скрипте это зависит от cwd и от оболочки; при отсутствии
совпадений shell передал бы литерал, и Playwright принял бы `*` за regex-квантификатор).

### Два слоя suites

| Слой | Naming | Роль | Входит в `test:e2e` |
|---|---|---|---|
| **Behavioral regression** | `*smoke.spec.ts` | поведение, ничего не пишет на диск | **да** |
| **Artifact capture** | `*screenshots.spec.ts` | пишет PNG в `design-memory/` | нет |

Разделение не косметическое. Screenshot-спеки **переписывают historical evidence**: запуск
`path-screenshots.spec.ts` (фаза D2A) против текущего кода перегенерировал доскриншоты D2A уже с
дизайном D2A-R1 — визуальная разница ~41 КБ, то есть история фазы была бы затёрта. Плюс шум
антиалиасинга (дельты 7–75 байт) грязнит дерево на ровном месте.

**Naming convention:** новый behavioral spec попадает в gate автоматически, если назван `*smoke.spec.ts`.
Новый artifact spec не должен так называться.

**Проверено:** после `npm run test:e2e` `git status --short design-memory/` пуст.

## 2. Fix B — progression зависел от development scenario

**Было:** CTA после завершения уровня 18 вёл на `/lessons/level.019?scenario=unlocked`, то есть
**dev-адаптер был единственным пользовательским механизмом разблокировки**. Без query тот же адрес
отдавал «закрыт» — последовательность обрывалась.

**Стало:** completion пишется в **сессию браузера**, а ссылка чистая — `/lessons/level.019`.

### Архитектура

Три роли строго разделены; правила не уехали в React-компоненты:

| Слой | Файл | Отвечает за |
|---|---|---|
| lesson state machine | `model/lesson-state-machine.ts` | завершён ли **текущий** урок |
| session progress adapter | `model/lesson-session-progress.ts` + `model/lesson-progress-store.ts` | хранение результата между navigation/reload |
| route availability resolver | `model/lesson-availability.ts` | объединение sequence + scenario (dev) + session |

Resolver — единственное место, где складываются три источника:

1. **curriculum sequence** — общий marker (`path-state.ts`), тот же, что читают Главная и Путь;
2. **session completion** — что пользователь реально прошёл в этой сессии;
3. **deterministic scenario override** — **только dev/tests**, применяется выше по стеку.

Порядок важен: сессия может только **открыть** уровень, которого не достигла последовательность.
Закрыть уже открытое или дать перепрыгнуть она не может — запись появляется лишь после завершения
предшественника.

### Storage

Ключ: `ata.lesson-progress.v1` — **версионированный**, чтобы смена схемы не переинтерпретировала старые данные.

```json
{ "version": 1, "completed": ["level.018"], "unlocked": ["level.019"] }
```

`sessionStorage`, **не** `localStorage`: прогресс не должен переживать сессию браузера — сверять его
не с чем, а долговечная запись подразумевала бы persistence, которой у продукта нет.

**Не хранится:** XP, финансовые значения, баланс, ответы пользователя сверх факта завершения,
curriculum copy, debug scenario. Проверяется тестом на самой сериализованной строке.

### Устойчивость к мусору

Любой сбой деградирует в сторону **locked** — безопасную:

- битый JSON, чужая форма, неизвестная версия → пустой прогресс;
- отравленные записи отбрасываются, валидные остаются;
- подделанное значение может только **закрыть**, никогда не открыть;
- битое значение **очищается**, а не гниёт в хранилище;
- `sessionStorage` может бросать (SSR, private mode, quota) — все обращения обёрнуты.

### SSR / hydration

Сервер `sessionStorage` **не читает** и всегда рендерит locked/safe default. Уровни, закрытые по
последовательности, отдаются `LessonSessionGate` — клиентскому компоненту на `useSyncExternalStore`:
server snapshot = `resolving`, client snapshot = реальный ответ. React меняет их после гидратации без
mismatch, и пользователь **не видит кадр неверного ответа** («закрыт» перед «открыт»).

Оба исхода — server-rendered поддеревья, переданные пропсами, поэтому модель не сериализуется, а решение
живёт в одном месте. Уровни, которые последовательность уже открыла (текущий урок), gate не проходят
и storage не ждут.

`LessonResolving` несёт eyebrow и **единственный h1**, поэтому документ всегда имеет заголовок, а ответ
не сдвигает вёрстку.

### Поведение

| Ситуация | Результат |
|---|---|
| до завершения уровня 18 | CTA уровня 19 **отсутствует** (не disabled) — только объяснение условия |
| `/lessons/level.019` без marker | sequence lock: «Сначала нужно завершить уровень 18» |
| после завершения | CTA «Перейти к уровню 19 «Разметка графика»», href **`/lessons/level.019`** |
| клик по CTA | уровень 19 открыт: честный practical placeholder, без query, без locked, без 404 |
| hard reload той же вкладки | остаётся unlocked |
| новый browser context | locked — marker'а нет |
| corrupt marker | locked, страница не падает |

Уровень 19 остаётся **practical placeholder**: фальшивая реализация практического задания не создаётся.
Он честно говорит, что открыт по последовательности, а задание появится позже, и даёт два выхода —
Путь и уровень 18.

### Что осталось от scenario

`?scenario=…` сохранён как **development/test adapter** и только: он seed'ит детерминированное
состояние для QA и тестов. **Ни одна пользовательская ссылка его не содержит** — проверяется тестом,
который перебирает все `<a>` на странице урока, на Главной и на Пути.

## 3. Честная граница

Закрытие сессии браузера может потерять прогресс. Это **не** баг, а граница frontend-only прототипа:
backend'а нет, и притворяться, что он есть, нельзя. UI говорит ровно это:

> «Отметка хранится только в текущей сессии браузера — сервер прогресса ещё не подключён.»

Не утверждается ни «сохранено на сервере», ни «прогресс синхронизирован». `localStorage`, cookie, URL
query и скрытые debug-флаги как замена **не используются**.
