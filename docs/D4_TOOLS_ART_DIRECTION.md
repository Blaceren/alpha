# D4_TOOLS_ART_DIRECTION — three directions for Tools + Trading Journal

**Фаза:** D4-A (art-direction gate) → **выбор сделан, D4-B реализован.**

> **Выбранное направление (D4-B, DD-308): «Structured Operational Spine»** — осознанный гибрид.
> **Tools Hub** = основа **Direction A «Operational Ledger»** (одна широкая вертикальная лента-нить
> инструментов; Trading Journal — текущий рабочий инструмент; locked/coming-soon — спокойные строки).
> **Trading Journal** = основа **Direction C «Structured Field Notebook»** (нумерованный spine, форма
> в голове потока, триптих ПЛАН → ИСПОЛНЕНИЕ → УРОК, урок доминирует, результат вторичен). Из A
> заимствованы спокойная временная структура, «Денежный результат не указан» и лёгкая форма добавления.
> **Direction B не используется.** Реализация — `src/features/tools/`, visual review —
> `docs/visual-reviews/D4_B_TRADING_JOURNAL.md`. Ниже — исходные три D4-A направления (сохранены как есть).

**Исходный статус D4-A:** React запрещён до явного выбора направления
(`ata-art-direction-gate`, CLAUDE.md workflow). **Победитель не выбран — выбирает пользователь.**

Три структурно разных направления для первого Tools vertical slice (scope —
`D4_TOOLS_SCOPE.md`). Каждое показывает **Tools Hub** и **Trading Journal** с одинаковым
fixture-контентом, чтобы сравнение было честным.

## Prototype implementation boundary

Прототипы изолированы в `design-memory/proposals/d4-tools/` (convention DD-260):
- линкуют **реальные** продуктовые ассеты — `src/styles/tokens.css`, `src/features/home/home.css`
  (shell: app bar / mobile top bar / bottom nav), self-hosted variable fonts; shell в каждом кадре —
  собственный shell продукта, не перерисованный;
- **не** попадают в `src/`, `BUILT_ROUTES` или production navigation;
- **не** пишут `localStorage`, не меняют progression, report lifecycle, Home / Path / Lessons;
- каждая RU-подпись ниже curriculum-слоя помечена как **prototype-only** (структура записи не
  канонична — `D4_TOOLS_SCOPE.md` §4.2);
- capture — `design-memory/proposals/d4-tools/capture.mjs` (ручной запуск, не e2e, DD-257),
  ровно 6 PNG в `design-memory/screenshots/d4-tools-art-direction/proposals/`, каждый 1440×900,
  horizontal overflow 0px во всех шести.

Ни один вариант не считается выбранным. Direction нельзя переносить в React до явного выбора или
явного запроса на слияние названных элементов из названных направлений.

## Общий fixture (одинаков во всех трёх направлениях)

**Hub** (канон для Артёма, L18): открыты **Trading Journal** (L10, featured/current) и
**Risk Calculator** (L15); locked previews — **Chart Markup Tool** («Откроется на уровне 20»),
**Indicator Checklist** («Откроется на уровне 25»). Risk Calculator в D4-A не реализуется.

**Trading Journal** — три записи (порядок и текст идентичны везде):
1. **XAU/USD · Продажа** — положительная; ручной результат **+18**; урок: терпение, вход по условию.
2. **EUR/USD · Покупка** — отрицательная; ручной результат **−7**; урок: поспешил, нарушил условие.
3. **GBP/USD · Наблюдение без входа** — **без денежного результата**; урок: пропуск — тоже решение.

Плюс точка добавления новой записи. Во всех направлениях текст урока — крупнейший элемент записи,
ручной результат — вторичная метка на полях; агрегатов (сумма / P/L / win rate / %) нет.

# Direction A — Operational Ledger

1. **Product thesis:** ATA превращает хаотичные действия трейдера в читаемую систему;
   инструмент — личный рабочий объект дисциплины, а не виджет.
2. **Concrete user moment:** Артём, уровень 18, после уроков открывает Инструменты, чтобы дописать
   разбор сегодняшней сделки — в потоке своих прошлых решений.
3. **Visual thesis:** один непрерывный **ленточный журнал** — светящаяся временная нить слева
   нанизывает каждую строку; журнал воспринимается как разбор решений, а не таблица.
4. **Stable DNA (манифест §A):** #2 luminous line used as structure, #6 fine contextual metadata,
   #5 chaos→system.
5. **Provisional idea (§B):** signal point / current-position marker — «голова» ленты (форма новой
   записи) как живая текущая позиция на нити.
6. **Signature object:** сама **лента-нить времени** с узлами; её функция — единый хронологический
   поток решений (на hub — порядок открытия инструментов по уровням).
7. **Spatial composition:** одна центральная колонка ≤860px; тонкая вертикальная нить слева, строки —
   метки на ней; почти нет отдельных контейнеров. **Не** sidebar+cards.
8. **Typography strategy:** display-заголовок страницы; урок записи — 15px primary (утверждение);
   инструмент/время — mono-метаданные 11–13px; план/исполнение — muted 12.5px.
9. **Materials strategy:** плоское navy-поле; нить — единственный светящийся элемент (gradient
   current→upcoming→locked); строки разделены hairline-дивайдерами, текущая строка — мягкий
   левый градиент-подсвет, не бордер-карта.
10. **Navigation strategy:** канон RU (Главная/Путь/Уроки/Инструменты/Ещё); внутри — прокрутка ленты;
    на mobile — последовательные переходы между записями.
11. **Progression strategy:** на hub узлы нити подписаны уровнями открытия (10 → 15 → 20 → 25),
    нить тускнеет к закрытым — прогресс читается геометрией нити.
12. **Alex Curie strategy:** не присутствует на этих поверхностях (инструмент — личное рабочее
    пространство пользователя); ментор появляется в review-контурах, не здесь.
13. **Motion strategy:** functional. Разворачивание записи и добавление — короткие (≤200ms) reveal;
    нить статична; никакого milestone-движения.
14. **Mobile transformation:** лента сжимается в узкую нить у левого края; строки — компактные;
    форма новой записи в один столбец; последовательная навигация «← Запись 02 / Запись 04 →».
15. **ASCII wireframe:**

    Desktop:
    ```
    +--------------------------------------------------------------+
    | [appbar: … Инструменты(current) …]                           |
    |  ← Инструменты · Trading Journal                             |
    |  Trading Journal                                             |
    |  (i) Записи вводятся вручную и не синхронизируются с брокером |
    |  |                                                           |
    |  ⊕──  Новая запись  [Когда][Инстр][Идея]  [Вывод…] [+Добавить]|
    |  |                                                           |
    |  ○──  16 июля · GBP/USD · Наблюдение                         |
    |  |    Пропуск — тоже решение…            (без результата)    |
    |  ○──  15 июля · EUR/USD · Покупка                           |
    |  |    Поспешил, нарушил условие…                    −7       |
    |  ○──  14 июля · XAU/USD · Продажа                           |
    |  |    Терпение сработало…                          +18       |
    +--------------------------------------------------------------+
    ```
    Mobile:
    ```
    +----------------------+
    | [mtop]               |
    | ← Инструменты · TJ   |
    | Trading Journal      |
    | (i) вручную…         |
    | |⊕ Новая запись      |
    | |  [Когда][Инстр]    |
    | |  [Вывод…] [+]      |
    | |○ 16 GBP/USD набл.  |
    | |  урок…  (без рез.) |
    | |○ 15 EUR −7 …       |
    | [← 02   04 →]        |
    | [bottom nav]         |
    +----------------------+
    ```
16. **Differs from D1A:** отклонённый D1A был сеткой одинаковых карточек с KPI; здесь нет ни карточек,
    ни сетки — одна нить и поток текста.
17. **Can't be renamed to another SaaS:** ledger-нить построена вокруг **разбора торгового решения**
    (план→исполнение→урок), где денежный результат намеренно вторичен — это анти-дашборд, а не
    журнал транзакций.
18. **Reference screenshots:** 01–02 (восходящая route trace как структура), 04 (нумерованная
    последовательность узлов).
19. **NOT transferred (§C):** декоративные цены, giant empty hero, постоянный bloom, низкий контраст,
    scroll-driven cinematic.

# Direction B — Trade Debrief Workspace

1. **Product thesis:** тот же тезис ATA; инструмент — рабочее место, где одна вещь в фокусе.
2. **Concrete user moment:** Артём открывает конкретную сделку EUR/USD, чтобы дописать вывод, видя
   рядом тихий архив остальных записей.
3. **Visual thesis:** **один доминирующий рабочий объект + подчинённая рейка архива** — верстак:
   то, над чем работаешь, занимает комнату; всё остальное — тихая полка сбоку, загружаемая в объект.
4. **Stable DNA (§A):** #4 one dominant meaningful object, #8 constructed object from lines/data/
   layers, #6 fine contextual metadata.
5. **Provisional idea (§B):** constructed artifact — открытая запись как объект, собранный из фаз
   (идея → план → исполнение → урок), с luminous-кромкой «живого объекта».
6. **Signature object:** **рабочая плоскость (stage)** с холодной светящейся левой кромкой; функция —
   текущий объект работы (на hub — инструмент, в журнале — открытая запись).
7. **Spatial composition:** намеренно **неравные** колонки ~1.9fr / 0.72fr; левая — доминирующая
   рабочая плоскость, правая — узкая рейка без самостоятельной жизни. **Не** two-column dashboard.
8. **Typography strategy:** крупное имя объекта (display 24px); фазы — mono-eyebrow-подписи + 14px
   secondary; урок фазы — 15.5px primary; рейка — 13.5px.
9. **Materials strategy:** одна выраженная поверхность (radial-подсвеченный surface-context, тонкий
   бордер, левая gradient-кромка); рейка — вообще без карт, только левые border-акценты.
10. **Navigation strategy:** канон RU; внутри — выбор элемента рейки грузит его в плоскость; на
    hub рейка ведёт к другим инструментам.
11. **Progression strategy:** на hub featured-инструмент — плоскость, будущие — тусклые строки рейки
    с «Откроется на уровне N»; прогресс = что сейчас в комнате vs что на полке.
12. **Alex Curie strategy:** не на этих поверхностях (личный инструмент); архитектурно рейка могла бы
    в будущем нести mentor-контекст, но в D4 — нет.
13. **Motion strategy:** functional. Смена активного элемента рейки — короткий crossfade плоскости
    (≤200ms); кромка статична.
14. **Mobile transformation:** плоскость сверху во всю ширину; рейка становится горизонтальной
    лентой/списком под ней (не боковой), «Новая запись» — над архивом.
15. **ASCII wireframe:**

    Desktop:
    ```
    +---------------------------------------------------------------+
    | [appbar: … Инструменты(current) …]                            |
    | ← Инструменты · Trading Journal                               |
    | Trading Journal   (i) вручную, без синхронизации              |
    | +-----------------------------+   ПОЛКА / АРХИВ               |
    | ▌ Разбор · 15 июля           |   [+ Новая запись]            |
    | ▌ EUR/USD  (Покупка)         |   ▏GBP/USD  16 июля           |
    | ▌ • Идея: отскок…            |   ▏Наблюдение · без рез.       |
    | ▌ • План: после свечи        |  ▐EUR/USD  15 июля (active)   |
    | ▌ • Сделал: раньше           |   ▏Поспешил · в разборе        |
    | ▌ • УРОК: поспешил…          |   ▏XAU/USD  14 июля           |
    | ▌ [ред.]      рез. −7        |   ▏Терпение · +18             |
    | +-----------------------------+                              |
    +---------------------------------------------------------------+
    ```
    Mobile:
    ```
    +----------------------+
    | [mtop]               |
    | ← Инструменты · TJ   |
    | Trading Journal      |
    | (i) вручную…         |
    | +------------------+ |
    | ▌ EUR/USD Разбор   | |
    | ▌ Идея/План/Сделал | |
    | ▌ УРОК: поспешил…  | |
    | ▌ рез. −7          | |

    | ▏GBP 16 · без рез.   |
    ```

16. **Differs from D1A:** D1A давал равные карточки без иерархии; здесь одна плоскость намеренно
    доминирует, а «полка» лишена собственного веса — противоположность равносетке.
17. **Can't be renamed to another SaaS:** доминирующий объект — **разбор конкретной сделки** с
    фазовой структурой решения и вторичным результатом; это не inbox и не CRM-record.
18. **Reference screenshots:** 02–03 (монументальный собранный объект-артефакт + signal-точка),
    01 (глубина слоёв).
19. **NOT transferred (§C):** giant empty hero, blur всех зон, декоративные цены, tiny tracked labels,
    низкий контраст.

# Direction C — Structured Field Notebook

1. **Product thesis:** тот же тезис ATA; инструмент — личный профессиональный полевой блокнот.
2. **Concrete user moment:** Артём ведёт блокнот сделок; открывает последнюю заметку по схеме
   план → исполнение → урок, остальные свёрнуты до одной строки-урока.
3. **Visual thesis:** вертикальный **Learning Spine** с нумерованными узлами; каждая заметка висит на
   узле, а внутри — явный триптих **ПЛАН → ИСПОЛНЕНИЕ → УРОК**.
4. **Stable DNA (§A):** #2 luminous line as structure (spine), #5 chaos→system, #6 fine contextual
   metadata.
5. **Provisional idea (§B):** vertical light ray → Learning Spine с нумерованными узлами (ref 04).
6. **Signature object:** **спайн с кольцами-узлами**; функция — ось последовательности (на hub —
   инструменты, нумерованные уровнем открытия; в журнале — заметки 01…N).
7. **Spatial composition:** одна колонка ≤820px со спайном слева (кольца 36px) и телом заметки
   справа; открытая заметка раскрывается в триптих in-place, без тяжёлых карт.
8. **Typography strategy:** display-заголовок; имя/инструмент 17px; mono-номера узлов; подписи фаз —
   10.5px tracked uppercase mono; урок-колонка — 14.5px primary и подсвечена.
9. **Materials strategy:** спайн — единственный светящийся элемент; заметки разделены воздухом, не
   бордерами; открытая заметка — тонкая левая cyan-кромка, триптих на hairline-разделителях.
10. **Navigation strategy:** канон RU; внутри — разворачивание/сворачивание заметки на месте.
11. **Progression strategy:** узлы спайна нумерованы уровнем открытия (10/15/20/25); закрытые — пунктир
    и приглушены; спайн физически показывает «от первого к последнему».
12. **Alex Curie strategy:** не на этих поверхностях; спайн — про личную дисциплину пользователя.
13. **Motion strategy:** functional. Раскрытие узла — короткий height/opacity reveal (≤200ms); спайн
    статичен, без постоянного bloom (в отличие от лендинга).
14. **Mobile transformation:** спайн уже, кольца сохраняются; триптих ПЛАН/ИСПОЛНЕНИЕ/УРОК из трёх
    колонок становится тремя вертикальными секциями; свёрнутые заметки — узел + строка-урок.
15. **ASCII wireframe:**

## Сравнительная таблица

| Ось | A — Operational Ledger | B — Trade Debrief Workspace | C — Structured Field Notebook |
|-----|------------------------|-----------------------------|-------------------------------|
| Пространственная система | одна лента-нить, поток | доминирующий объект + рейка | нумерованный спайн из заметок |
| Signature object | временная нить с узлами | рабочая плоскость с кромкой | спайн с кольцами-узлами |
| Геометрия навигации/прогресса | вертикальная хронология | фокус ↔ периферия | последовательная ось 01…N |
| Форма новой записи | встроена в голову ленты | ghost-кнопка над архивом | узел «+» вверху спайна |
| Разбор записи | план/исполнение инлайн в строке | фазы в доминирующей плоскости | явный триптих ПЛАН/ИСПОЛН/УРОК |
| Featured Trading Journal | текущая строка ленты | плоскость-объект с пиком записей | открытый узел спайна |
| Locked previews | тусклые строки той же ленты | тихие строки рейки | пунктирные узлы спайна |
| Основная сила | плотность и непрерывность потока | ясный единственный фокус | видимая методология разбора |
| Основной риск | плотность может утомлять при росте | правая рейка недоиспользована на широком экране | триптих сжат при узкой ширине |
| Reuse для будущих Tools | высокий (любой tool — строка ленты) | высокий (любой tool — объект в плоскости) | средне-высокий (tool — узел спайна) |
| Reference-опора | 01–02, 04 | 02–03, 01 | 04, 02 |

**Победитель не выбран — направление выбирает пользователь.** React не начинается до явного выбора
или явного запроса на слияние названных элементов из названных направлений (D4-B).
