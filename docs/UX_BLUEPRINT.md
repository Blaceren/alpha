# UX_BLUEPRINT.md — Alfa Trade Academy CRM

> Phase 0 (обновлено в Phase 0.5) · UX-блюпринт. Desktop-first операционный интерфейс: плотный, быстрый, объяснимый, клавиатурный.
> Статус: Draft для утверждения. Не содержит визуального брендинга — только структура и поведение.
>
> **Phase 0.5:** добавлены раздельные бейджи 5 измерений состояния, bucket-aware `MoneyCell`, PII Reveal-flow, SLA-состояния (paused/warning/breached), Reset mock environment.

---

## 0. Принципы (из PROJECT_CONTEXT §20)

CRM — **рабочий инструмент, не декоративный дашборд**. На каждом экране сотрудник должен видеть: что требует внимания, почему, что делать, кто отвечает, когда дедлайн, какой результат ожидается.

**Запрещено:** случайные декоративные графики; большие пустые hero-блоки; цвет без семантики; непрозрачные AI-scores; финансовые данные без timestamp/freshness; действия без confirmation и audit.

---

## 1. Desktop layout

Трёхзонная сетка, оптимизированная под ширину ≥1280px:

```
┌────────────────────────────────────────────────────────────┐
│ Top bar: ⌘K search · env=MOCK · role · density · profile     │
├────────┬───────────────────────────────────────┬───────────┤
│        │                                       │           │
│Sidebar │      Primary content (list/detail)    │  Context  │
│ (nav)  │                                       │  panel    │
│ 240px  │            fluid                      │  360px    │
│        │                                       │(collapsible)│
├────────┴───────────────────────────────────────┴───────────┤
│ Optional status/footer (selection count, bulk actions)      │
└────────────────────────────────────────────────────────────┘
```

- **Списковые экраны** (Users, Tasks, Cases, очереди): центр — таблица, правая панель — превью выбранной строки.
- **User 360:** центр — секции карточки (табы/якоря), правая панель — постоянные Operations (tasks/notes/signals/recommended actions), фиксированный header сверху.
- Правая панель сворачивается для максимума ширины таблицы.

---

## 2. Sidebar

- Постоянная левая навигация, сгруппированная (Today · WORK · QUEUES · OPERATIONS · INSIGHT · Settings) — как в IA §1.
- Активный раздел подсвечен; счётчики-бейджи (напр. overdue tasks, SLA-риски) справа от пункта.
- Свернутое состояние (только иконки) для узких экранов/по желанию.
- Разделы, недоступные роли, **скрыты** (не disabled), чтобы не создавать шум.
- Внизу: индикатор окружения **MOCK DATA** и версия сборки.

---

## 3. Command palette / глобальный поиск (⌘K)

- Открывается по ⌘K / Ctrl+K из любого места.
- Возможности: перейти к пользователю (по имени/ID/masked email), перейти в раздел, выполнить действие («создать задачу», «открыть Today»), открыть saved view.
- Результаты сгруппированы (Users · Navigation · Actions · Saved views), с клавиатурной навигацией (↑↓, Enter, Esc).
- Поиск пользователей идёт через `searchUsers`; показывает lifecycle-бейдж и owner в строке результата.

---

## 4. Таблицы

- **Плотность прежде всего:** компактные строки, моноширинные числа для сумм/уровней, выравнивание чисел по правому краю.
- **Колонки:** конфигурируемые (показать/скрыть/переставить), с разумными дефолтами по разделу (см. IA §4).
- **Сортировка:** по клику на заголовок; индикатор направления; серверная сортировка через provider.
- **Строка:** клик → правая панель-превью; двойной клик / Enter → полный переход (User 360).
- **Пиннинг:** первая колонка (пользователь) sticky при горизонтальном скролле; заголовок sticky при вертикальном.
- **Выбор:** чекбоксы для будущего bulk (v1 — визуально готово, действия отключены с подсказкой «coming soon»).
- **Числовые/финансовые ячейки:** всегда с freshness-иконкой; stale — приглушённый цвет + tooltip «обновлено N ч назад»; без права — маскированный диапазон.

---

## 5. Фильтры

- Панель фильтров над таблицей: чипы активных фильтров + кнопка «+ фильтр».
- Типы: мультиселект (lifecycle, signals, owner, pocket, checkpoint), диапазоны (balance, net deposits — только при Exact financials), дата (last action before), булевы (has active case, unassigned).
- Комбинируются по И; активные фильтры показаны как удаляемые чипы; «Очистить всё».
- Состояние фильтров синхронизируется с URL (shareable) и может быть сохранено как view.

---

## 6. Saved views

- Сохранённая комбинация: фильтры + сортировка + конфигурация колонок + плотность.
- Личные и (для manager/retention) командные views.
- Быстрый доступ из шапки списка (dropdown) и из ⌘K.
- Системные views = сегменты (read-only базовые), поверх которых можно «сохранить как свой».

---

## 7. Панели (right context panel)

- **Preview-панель** (из списков): краткая сводка пользователя/задачи/кейса + быстрые действия (открыть User 360, создать задачу, назначить owner).
- **Operations-панель** (в User 360): вкладки Signals · Recommended actions · Tasks · Notes; всегда видна.
- Панель не блокирует таблицу; закрывается Esc; ширина фиксирована (360px) с возможностью свернуть.
- Каждое действие в панели → confirmation (для изменяющих) → запись в Audit (mock).

---

## 8. Timelines

- Вертикальная хронология (`at desc`), сгруппированная по дням.
- Каждый элемент: иконка источника (product/pocket/employee/communication/automation/lifecycle/signal/task/case), заголовок, краткое summary, время, actor.
- Фильтр по источнику (чипы-переключатели) и по диапазону дат.
- Раскрытие элемента → evidence (основание). HIGH-события маскируются без права.
- Инкрементальная подгрузка (курсор), «загрузить ещё»/бесконечный скролл.
- Timeline — визуальное ядро объяснимости; никаких событий без источника и времени.

---

## 9. Статусы (визуальная семантика)

- **Приоритет:** critical / high / medium / low — единая шкала цветов, применяется одинаково в Today, списках, панелях.
- **Состояние (5 измерений, STATE_MODEL):** отдельные бейджи для **LifecycleStage**, **FundingStatus**, **EngagementStatus** (по одному) + **чипы** для **ValueSegment[]** и **OperationalBlocker[]**. Каждый — с tooltip (reason + evidence + calculatedAt/enteredAt). Не смешивать измерения в один бейдж.
- **Task/Case status:** цветовые бейджи; overdue/SLA-breach — акцентный (напр. красный) с иконкой.
- **Checkpoint:** approaching (внимание) / grace (таймер) / suspended (блок) / restored (успех) — разные семантические цвета.
- **Freshness:** fresh (нейтр.) / stale (приглушённый + иконка часов).
- Правило: **цвет только со смыслом**; одинаковый статус = одинаковый цвет везде; не полагаться только на цвет (иконка/текст дублируют — см. §13).

---

## 10. Alerts / уведомления

- **Inline-баннеры** для контекстных предупреждений (stale data, data conflict, SLA breach) — над соответствующим блоком, с действием.
- **Toast** для результатов действий (создано/назначено/ошибка) — недолгие, недоминирующие.
- **Confirmation-диалоги** для всех изменяющих действий, с явной пометкой mock/local и полем reason при необходимости.
- Никаких модальных «стен» без действия; alert всегда предлагает следующий шаг.

---

## 11. Empty / loading / error states

- **Empty:** осмысленный текст «почему пусто» + предложение действия (напр. «Нет задач на сегодня — проверьте очередь команды»). Не пустой белый экран, но и не декоративный hero.
- **Future checkpoint (D-10):** при `future_checkpoint_not_defined` (после L100) показывать «Следующая программа находится в разработке» — без суммы и без фальшивого прогресс-бара.
- **PII reveal (D-11):** полный email по умолчанию скрыт; действие Reveal → диалог reason code → показ с таймером авто-скрытия; событие в Audit.
- **Loading:** скелетоны строк/карточек (не спиннер на весь экран); частичная отрисовка, если часть данных готова.
- **Stale:** данные показываются + бейдж «устарело N ч назад» + кнопка обновить.
- **Error:** понятное сообщение по `CrmErrorCode` (`unauthorized` → «нет доступа»; `upstream_unavailable` → «источник недоступен, повторить»; `conflict` → «расхождение данных, открыть case»); retriable → кнопка «Повторить».
- Каждое состояние спроектировано для **каждого** списка/панели, не только для «счастливого пути».

## 12. Responsive behavior

- **Desktop-first.** Оптимум ≥1280px. От 1024–1280px — правая панель сворачивается автоматически.
- <1024px (планшет) — поддерживается для просмотра: sidebar → иконки, таблицы → горизонтальный скролл с sticky-колонкой, панель → overlay.
- Мобильные телефоны **не** целевой сценарий v1 (интерфейс операторский); минимальная деградация — читаемость, без полноценной работы.
- Плотные таблицы не «ломаются» в карточки на десктопе; карточный режим — только на узких экранах при необходимости.

---

## 13. Accessibility

- Полная клавиатурная навигация: Tab-порядок, ⌘K, стрелки в таблицах/списках, Enter/Esc, горячие клавиши для частых действий (документируются).
- Фокус всегда виден; focus trap в диалогах/панелях.
- ARIA-роли для таблиц, диалогов, тостов, таймлайна; live-region для алертов.
- Контраст ≥ WCAG AA; **не полагаться только на цвет** — статусы дублируются иконкой/текстом.
- Уважение `prefers-reduced-motion` (минимум анимаций); анимации функциональны, не декоративны.
- Масштабируемый текст без поломки лэйаута.

---

## 14. Density modes

- Два режима: **Comfortable** и **Compact** (по умолчанию Compact для операторов), переключатель в top bar; выбор запоминается (локально).
- Compact уменьшает высоту строк/паддинги, сохраняя кликабельность (min touch/hit target).
- Density — часть saved view.

---

## 15. Visual semantics (сводные правила)

1. Цвет несёт смысл (приоритет/статус/freshness), нигде не декоративен.
2. Числа — моноширинные, финансы — всегда с freshness и (при отсутствии права) маскированы.
3. Одинаковая сущность выглядит одинаково во всех разделах (единый компонентный язык: Badge, StatusPill, FreshnessTag, PriorityDot, EvidencePopover).
4. Каждое изменяющее действие: confirmation → mock-пометка → Audit.
5. Никаких непрозрачных score — только объяснимые сигналы с evidence.
6. Пустое пространство работает на читаемость, а не на «воздух ради красоты».
