## 2. Почему это не generic task dashboard

Если заменить заголовок на «Задачи» / «Дашборд», страница перестанет быть правдой:

- **Очередь — не список задач, а вывод.** Членство считает `BASIS_MEMBERSHIP` из сигналов и состояния; задача не «создаётся» и не «закрывается». Пользователь исчезнет из очереди, когда исчезнет основание, а не когда кто-то нажмёт «готово».
- **У каждой строки есть доменное основание, а не заголовок.** «Расхождение данных баланса продукт↔Pocket.» — это вывод сигнального движка по фикстуре, а не введённый текст.
- **Спокойные пользователи физически отсутствуют.** 30 в датасете, 22 в очереди; 7 без сигналов не попадают вообще. Дашборд показал бы всех и добавил фильтр.
- **Проекция по ролям меняет содержимое строки.** Один и тот же пользователь для admin — «До checkpoint L10 осталось 5%» + «$95», для support — «Контрольная точка требует проверки.» + «$50–99». Generic-дашборд не знает про checkpoint-сетку и реконструкцию суммы.
- **Приоритет — правило, а не поле.** `critical` приходит из упорядоченной лестницы, а не из выпадающего списка.
- **Нет ни одной мутации.** Дашборд задач без «выполнить» бессмысленен; Today без мутаций — полноценен, потому что его работа: понять → отсортировать → открыть User 360.

### Осознанно не исправлено

- **«Grace period активен, завершится через 6ч.»** — текст сигнала из Phase 1B1. «Grace period», «checkpoint», «Pocket», «SLA» — принятые доменные термины проекта (ср. `FUNDING_LABEL.checkpoint_grace = "Grace-период"`), а не internal enum labels. Переписывание reason-строк сигнального движка вне scope 1B3.
- **`RECOMMENDATION_CATALOG.title` ≠ `RECOMMENDATION_LABEL`** — предсуществующее расхождение: Users рендерит `RECOMMENDATION_LABEL`, User 360 — `title` из проекции. Today встал на сторону объявленного единого источника. Починка самого расхождения затронула бы User 360 и выходит за §35.
- **Дубль DOM (desktop-строка + mobile-карточка, одна скрыта CSS)** — существующий паттерн Users Workspace; менять его в 1B3 значило бы трогать чужой feature.
