# PATH_LAYOUT_ENGINE — детерминированная геометрия Пути

## Принцип

100 координат вручную не хардкодятся. Layout вычисляется из данных модуля и прогресса:
одинаковый вход → одинаковый выход, всегда. Без `Math.random`, без непрерывного
`requestAnimationFrame`, без измерений DOM.

## Слои и единицы

Все координаты — **проценты (0–100 × 0–100) одного контейнера** (`.path-canvas`).
DOM-узлы позиционируются `left/top: %`, слой соединений — SVG `viewBox="0 0 100 100"
preserveAspectRatio="none"` с `vector-effect: non-scaling-stroke`. Так DOM и SVG делят одну
координатную систему и не расходятся ни на одном размере (урок из D1B, где выравнивание SVG↔DOM
было главной болью).

## computeModuleLayout(module, progress) → ModuleLayout

Вход: модуль (4–6 уровней, последний — checkpoint) + прогресс-маркер.
Выход:

- `nodes: NodeAnchor[]` — x равномерно `11%…82%`; y восходит `74%→32%` с детерминированной
  «походкой» `WALK = [0,5,-3,4,-2,3]` (осмысленные шаги последовательности, не шум);
  `labelSide` чередуется по чётности (labels не сталкиваются); ворота — без walk-смещения.
- `connections: ConnectionSegment[]` — сегменты между соседними узлами; вид из прогресса:
  `completed` (сплошной зелёный) · `upcoming` (синий от текущего) · `future` (штрих) ·
  `distant` (точечный за пределами модуля).
- `boundary` — вертикальная граница входа в модуль.
- `gate` — вертикаль ворот на узле checkpoint (две смещённые плоскости + апертура рисуются
  viewport-ом по этому якорю).
- `branch?` — ответвление инструмента от ворот (когда checkpoint открывает tool).
- `entryStub?/exitStub?` — приглушённые продолжения к соседним модулям (совершённый вход —
  зелёный, будущее — distant).

## VisiblePathWindow

`computeVisibleWindow(moduleIndex, progress)` — окно = **один модуль** (клампится 1–20) +
ссылки на соседние модули для рёбер-переходов. Смена окна: лента модулей, рёбра, клавиатура
(пересечение границы), return-to-current.

## Почему изгибы объяснимы

Каждый перелом маршрута = один уровень последовательности; вертикаль слева = граница модуля;
вертикаль справа = ворота контрольной точки; пунктирное ответвление вверх = инструмент;
точечные хвосты = соседние модули. Ничего декоративного без функции; на график цены не похоже
(нет осей, цен, свечей).

## Производительность

Окно одного модуля: ≤8 DOM-узлов, ≤30 SVG-элементов (закреплено e2e-тестом
`performance envelope`). Автоцентрирование на mobile — единичный `scrollTo` при смене выбора
(smooth, при reduced motion — instant), не цикл.
