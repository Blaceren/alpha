# ACCOUNT RECOVERY V1 — screenshot review

- **Date:** 2026-10-01
- **Scope:** password reset (`/forgot-password`, `/reset-password`), confirmation of the address
  (`/verify-email`), change of the address (`/confirm-email`), «Забыли пароль?» on `/login`, the
  confirmation notice on `/register`, and the email row of `/profile`.
- **Owner, 2026-10-01:** «давай сделаем функционал для пользователей: сброс пароля / восстановление
  пароля, подтверждение и смена почты». Answers the same day: the mail channel is connected on PROD,
  this is the foundation; confirmation is soft; nothing is checked by mail on PREPROD; learners only.
- **Design source: no new composition.** Every new screen is a state of a surface the owner has
  already accepted:
  - the four link pages and the reset request stand on the auth stage (`AuthStage`, the frame with
    its two corner marks, the serif heading, one Signal action) — the page a learner signs in on;
  - the email block is rows of the profile's own grammar (label · value · one text affordance, an
    editor that opens in place, one editor at a time).
  Because nothing structural was invented, the art-direction gate (three low-fi compositions and a
  choice) was not run. That is a judgement, and it is stated to the owner in the report.

## Visual thesis

A recovery screen is the threshold again, saying one thing: what happened to the link, and the one
action left. The frame that «marks a decision» on sign-in marks it here; a state never offers two
buttons. In the profile the address is a value like the name, its state is said after it in the
quiet tone, and a change is shown as PENDING — the page never claims an address has changed until
the new mailbox answered.

## How the screenshots were made

- **Real browser:** Playwright Chromium (headless), `deviceScaleFactor` 1, locale ru-RU, at
  1440×900, 1024×768, 768×1024 and 390×844; fonts awaited (`document.fonts.ready`); full-page.
- **Stand:** Academy dev `127.0.0.1:3298` → Backend dev `127.0.0.1:3299`, a throwaway SQLite copy
  with migration `20261001120000_account_action_token` applied by the real runner,
  `MAIL_TRANSPORT=outbox` (messages are JSON files), Turnstile on Cloudflare's published test keys —
  hence the «Только для тестирования» strip in the widget, which is the test key's own.
- **One synthetic learner per run**, registered through the form; addresses and passwords are
  generated by the script and never printed. Links are taken from the outbox files and opened as a
  mail client opens them (a tab of their own).
- **Dev-only artefact:** the Next.js dev indicator is hidden by an injected rule; nothing else is.

## The chain, end to end (42 checks, all passing)

Registration → the confirmation message → the profile says «не подтверждён» → «Отправить письмо» →
the link opened on a device that is NOT signed in: the token leaves the address bar, opening confirms
nothing, the button does → the same link does not work twice → a link pasted into the tab that says
«ссылка неполная» is read → the profile says «подтверждён».
Change of address: a wrong password is refused and the field emptied → pending, address unchanged →
the new mailbox gets the link, the old one a notice with the new address masked and no link →
cancel kills the link → a change of password withdraws a pending change and kills its link, and the
account's address is told → the change confirmed from the new mailbox → the old address is told →
the profile shows the new address.
Reset: the screen is word for word the same for a known and an unknown address, and the unknown one
is sent nothing → the link goes to the account's current address only → the token leaves the address
bar → the open session is closed by the reset, and the reset signs nobody in → the previous password
and the old address no longer sign in; the new ones do. No message contains a password.

## Fixes applied

1. **Marks, narrow tier:** widths per side (`border-top-width` + `border-left-width`, `border-right-width`
   + `border-bottom-width`) — a corner has two sides.
2. **Marks, compressed tiers:** two blocks of their own (the tiers themselves stay «spacing and
   nothing else», as `auth-threshold-layout.test.ts` pins them), with no new breakpoint: 24px marks
   with 5px bars inset 4/10/5 on a short viewport, 18px with 4px bars inset 3/9/4 on a phone. Bars
   live in the padding; the top-left mark ends before the heading begins.
3. **Fields (`.p-field`), both profile forms:** the edit rule (`--p-locus-rule-edit`, 3.04:1) under
   every field, the operable measure as width, field scale 18px instead of identity scale 28px.
4. **Hint clearance** (`--p-rhythm-inline`) and **refusal-to-actions distance** (`--p-rhythm-locus`).
5. **Note rows** keep the height of a row with an affordance from 600px up.
6. **Reset lead:** «Ссылка из письма позволяет один раз задать новый пароль.» — true in every state.
7. **`hashchange`** is listened for on both link pages; the pasted link's token leaves the address bar too.

**Automatic-fail check.** No signature object → PASS on the stage (the frame with its marks and the
brand axis); the profile block has none of its own and borrows nothing decorative — it is a row of
an accepted functional page, scored 6. Renamable to any SaaS → PASS (serif threshold voice, the
frame, Signal used for the one action only). Sidebar + card grid → PASS (neither). Mobile is a
stacked desktop → PASS for the stage (axis becomes the mark above the frame, three compression
tiers); the profile is a list and stays a list, affordances drop under their values. More than six
identical cards → PASS (no cards). All surfaces one shape → PASS. Icon-only identity → PASS (no
icons carry meaning). Body contrast → PASS (quiet tone 5.06:1, field rule 3.04:1).

**Objective counts.** Same-type cards: 0 / 0. Surface geometries: 3 (frame, field, action) / 2
(ruled row, action). Icon dependence: 0%. Branded objects: 2 (mark, frame) / 0. Hierarchy levels:
4 / 4. Contrast problems: none after fix 3. Unadapted landing-only patterns: none.

**Verdict: PASS** (85 and 80; no automatic fail). The lower score is the honest one for a row added
to a functional page: it earns its place by being exact, not by being memorable.
