# D2C — Lessons Library & Module Overview («Библиотека уроков и обзор модуля»)

Фаза **D2C** впервые получает определение. До этой задачи «D2C» существовал в документации только в
форме отрицания («D2C автоматически не начинается»): ни scope, ни non-scope, ни acceptance у него не
было. Этот документ фиксирует определение; **производственная реализация не начата** (см. §8).

Baseline: `eea3c1f898db6fcecb72145dbc78c6c77c79b823` (`fix: complete ATA lesson acceptance gate`).

---

## 1. Определение

**D2C = Lessons Library & Module Overview.** Основной production-маршрут: **`/lessons`**.

Сегодня `/lessons` — это redirect на текущий урок (`/lessons/level.018`), введённый в D2B, чтобы пункт
навигации «Уроки» перестал отдавать 404. D2C превращает `/lessons` в **собственную страницу**: обзор
учебного содержания. Контекстный дефолт «перейти к текущему уроку» при этом никуда не исчезает — он
становится доминирующим действием страницы, а не редиректом.

### Назначение страницы

- дать пользователю обзор учебного содержания;
- показать модули и входящие в них уровни;
- помочь быстро продолжить текущий урок;
- позволить вернуться к уже пройденному материалу;
- показать тип следующего учебного шага;
- **не** дублировать последовательную карту Пути.

---

## 2. Различие «Путь» и «Уроки» (принципиальное)

Две страницы отвечают на **разные вопросы**, и это различие — главный критерий приёмки D2C. Если
«Уроки» начинают отвечать на вопросы Пути, страница не нужна.

| | **Путь** (`/path`, D2A) | **Уроки** (`/lessons`, D2C) |
|---|---|---|
| Вопрос | «Где я в последовательности?» | «Чему посвящён материал?» |
| Отвечает | где пользователь находится в последовательности; какие уровни открыты; где checkpoint; какие требования впереди; какой следующий обязательный шаг | чему посвящён текущий модуль; какие уроки в него входят; какой материал уже изучен; какой урок продолжить; какие форматы уроков существуют; какие материалы можно пересмотреть |
| Природа | **карта прогресса** — положение и допуск | **содержание** — материал и его состав |
| Геометрия | Route Field: диагональная траектория, viewport-рамка, узлы в пространстве | список/индекс/бриф — **не** маршрут (направление выбирается в D2C-A) |
| Единица | уровень как **узел маршрута** | урок как **учебный материал** |
| Время | «что дальше» | «что уже есть» + «что продолжить» |

**Правило:** Путь показывает **допуск**, Уроки показывают **материал**. Финансовое условие checkpoint
на «Уроках» присутствует только как **граница модуля** (структурный факт «дальше — контрольная точка,
условие: баланс Pocket от $200»), а не как призыв.

## 3. Scope будущей production-фазы D2C

- route **`/lessons`** как самостоятельная страница;
- **доминирующее «Продолжить обучение»** — один очевидный следующий шаг;
- overview текущего модуля;
- навигация между 20 модулями;
- список уровней выбранного модуля;
- статусы уровня: **завершён · текущий · доступен · закрыт последовательностью · checkpoint ·
  practical assignment**;
- тип учебного шага (kind);
- **длительность — только когда она реально известна** (см. §5);
- ссылки на доступные уроки;
- возврат к завершённым урокам (пересмотр);
- responsive desktop / tablet / mobile;
- 200% zoom;
- canonical desktop/mobile navigation;
- переиспользование существующих curriculum fixtures и state models (§6).

## 4. Non-scope D2C

Не входит и **не имитируется**: отчёты; mentor feedback; проверка отчётов; редактор контента; CMS;
отдельная test route (`/lessons/[levelCode]/test` остаётся зарезервированной, DD-242); практическое
задание уровня 19 (остаётся честным placeholder'ом); backend progress; Pocket; XP-rewards; новые
checkpoint rules; новый curriculum; поиск по всему продукту; AI-рекомендации; мутации; **D3**.

## 5. Канонический сценарий

Единственный сценарий для всех трёх направлений — **существующая каноническая история**, целиком
прочитанная из typed fixtures (`src/data/curriculum/fixture.ts`, `src/features/lesson/data/lesson-fixtures.ts`):

| Факт | Значение | Источник |
|---|---|---|
| Пользователь | Артём | shell (`AppShell userName`) |
| Модуль | 04 «Чтение графика» | `MODULE_ROWS[4]` |
| Описание модуля | «Свечи, тренд и диапазон, уровни поддержки и сопротивления, разметка.» | `MODULE_ROWS[4]` |
| Уровни модуля | 16 «Свечи» · 17 «Тренд и диапазон» · 18 «Поддержка и сопротивление» · 19 «Разметка графика» · 20 «Контрольная точка $200» | `LEVEL_ROWS` |
| Текущий урок | 18 «Поддержка и сопротивление», kind `video-test` | `LEVEL_ROWS`, D2B fixture |
| Цель урока 18 | «Научиться читать поддержку и сопротивление как области реакции рынка, а не как точные линии.» | `LEVEL_18.goal` |
| Следующий шаг | 19 «Разметка графика», kind `practical`, артефакт «Разметка 3 графиков» | `LEVEL_ROWS` |
| Прогресс модуля | 2 из 5 | сценарий (16, 17 завершены) |
| Checkpoint | уровень 20, порог **$200** | `CHECKPOINT_ROWS[20]` |
| Награда checkpoint | **Chart Markup Tool**, ранг **Наблюдатель IV**, канал **Разбор графиков** | `CHECKPOINT_ROWS[20]`, `rankLabel(observer, 4)` |
| Длительность урока 18 | **8:00** (480 c) | `L18_DURATION_SECONDS` |

### Что является prototype-only placeholder'ом

Честная граница: **длительность известна ровно для одного уровня — 18** (детерминированный
simulated-медиаадаптер D2B, DD-244). У остальных 99 уровней длительности **не существует**, поэтому в
прототипах она **нигде не показана и не выдумана**. Правило «длительность только когда реально
известна» в D2C означает буквально: сегодня это один уровень.

Названия модулей и уровней **не выдуманы**: все 20 модулей и все упомянутые уровни взяты из fixture.

Prototype-only UI-строки (не curriculum, не канон): подписи вида «Видео-урок и тест», «Практическое
задание», «Завершён», «Откроется после уровня 18», «Продолжить обучение», роли цепочки в Concept C.
Формулировки kind согласованы с уже существующими строками продукта
(`path-detail-layer.tsx`: «Видео-урок и тест», «Практическое задание»), но **канонического
`kindLabel`-словаря в коде нет** — его введение относится к реализации D2C, а не к арт-дирекшену.

## 6. Что должно быть переиспользовано (не переписано)

| Слой | Файл | Роль в D2C |
|---|---|---|
| curriculum (типы) | `src/domain/curriculum.ts` | `CurriculumModule`, `CurriculumLevel`, `CurriculumLevelKind`, `CheckpointDefinition`, `formatThresholdUsd` |
| curriculum (данные) | `src/data/curriculum/fixture.ts` | `CURRICULUM`, `getModuleByIndex`, `getModuleForLevel`, `getLevel`, `getNextCheckpoint` — **единственный** источник структуры |
| прогресс/состояния | `src/features/path/model/path-state.ts` | `PathProgress`, `moduleAggregateState`, `moduleCompletedCount` — тот же marker, что читают Главная и Путь |
| доступность уровня | `src/features/lesson/model/lesson-availability.ts` | resolver: sequence + dev scenario + session (DD-256). «Уроки» **обязаны** спрашивать его, а не решать сами |
| сессионный прогресс | `lesson-session-progress.ts`, `lesson-progress-store.ts` | завершённость в рамках сессии |
| контент урока | `src/features/lesson/data/lesson-fixtures.ts` | goal, media.durationSeconds, `contentProvisional` |
| ранги | `src/domain/progression.ts` | `rankLabel` |
| shell | `src/components/shell/app-shell.tsx` | app bar / mobile top / bottom nav — **без изменений** |
| навигация | `src/config/navigation.ts` | канонические RU-подписи и маршруты |
| токены | `src/styles/tokens.css` | provisional semantic tokens |

**Запрет на дублирование:** D2C **не заводит** второй источник структуры курса, второй словарь
состояний и вторую копию правил доступа. Новое, что вправе появиться: presentation-компоненты
страницы и (возможно) `kindLabel`-словарь как единственный владелец подписей типов.

## 7. Предпосылка к устранению до/во время D2C

**Пункт навигации «Уроки» помечен как непостроенный, хотя маршрут работает с D2B.**
`src/components/navigation/desktop-route-navigation.tsx:5` и
`src/components/navigation/mobile-bottom-navigation.tsx:6` содержат
`const BUILT_ROUTES = new Set(["home", "path"])`, поэтому «Уроки» рендерятся как
focusable-disabled кнопка с подсказкой «Скоро» — при живом `/lessons`. Это прямое противоречие DD-254
(«адресаты, построенные в D2B, становятся настоящими»).

Прототипы D2C-A показывают «Уроки» **активным пунктом** (`aria-current="page"`) — так, как обязана
выглядеть страница. Правка production-кода в D2C-A **не выполнялась** (фаза art-direction не трогает
`src/`); это первый пункт работ реализационной фазы D2C.
