## 1. Что такое «Инструменты»

**Инструменты (Tools)** — набор рабочих продуктовых объектов, которые пользователь **вручную**
ведёт по мере прохождения пути. Инструмент — не виджет дашборда и не отчёт брокера: это
**личный рабочий инструмент дисциплины и разбора решений**, который открывается на конкретном
уровне и остаётся доступным дальше.

Инструменты продолжают ядро продукта — переход от хаотичных действий к легко читаемой системе
(`ata-brand-language`, chaos→system). Каждый инструмент — один осмысленный объект с одним
очевидным следующим шагом, а не сетка одинаковых карточек.

**Что Tools НЕ является** (канон ATA):
- не торговый терминал и не имитация терминала;
- не дашборд с KPI;
- не сводка баланса / P/L / доходности;
- не marketplace / каталог приложений;
- не автоматический импорт сделок из Pocket или иного брокера.

## 2. Unlock — через существующий progression resolver

Инструменты открываются **контрольными точками** ровно так, как уже задано в curriculum
(`src/data/curriculum/fixture.ts`, `CHECKPOINT_ROWS`). Отдельной unlock-логики Tools **не
вводит** — доступность выводится из того же резолвера, что и уровни/уроки. Никаких новых
thresholds, никаких выдуманных условий.

Канонические первые unlock'и (из fixture, дословно):

| Уровень | Инструмент (name) | Код |
|--------:|-------------------|-----|
| 10 | Trading Journal | `tool.trading_journal` |
| 15 | Risk Calculator | `tool.risk_calculator` |
| 20 | Chart Markup Tool | `tool.chart_markup` |
| 25 | Indicator Checklist | `tool.indicator_checklist` |

Всего в curriculum 19 инструментов (L10–L100) + 1 referral-gated «Секретный» = 20 в интерфейсе
(`docs/CURRICULUM_AND_UNLOCKS.md`). Для канонического пользователя **Артёма (L18)** открыты
**Trading Journal (L10)** и **Risk Calculator (L15)**; следующие (L20, L25, …) — locked previews.

Locked-инструмент показывает **только**: имя (или нейтральный плейсхолдер) и подпись
«**Откроется на уровне N**». Без fake CTA, без активной внутренней функциональности, без
countdown, без «осталось X уровней».

`BUILT_ROUTES`. Пункт «Инструменты» в `src/config/navigation.ts` остаётся как есть.

## 4. Первый инструмент — Trading Journal

**Unlock target: Level 10.** Первый и featured-инструмент первого vertical slice.

Trading Journal — место, где пользователь **вручную** ведёт записи об **отдельных** сделках и
решениях. Ценность записи — **в тексте разбора** (план → исполнение → вывод), а не в цифре
результата.

### 4.1 Природа: browser-local, ручная

- Всё вводится **вручную**. Автоподгрузки из брокера нет.
- Хранение — **browser-local** (та же модель, что report-workspace: `localStorage`), не серверная
  синхронизация. **Ключ (зафиксирован в D4-B): `ata.tools.trading-journal.v1`, версия 1**
  (`docs/TOOLS_STORAGE.md`, DD-310).
- Обязательная честная подпись на поверхности инструмента:

  > «Записи вводятся вручную и не синхронизируются с брокером.»

### 4.2 Минимальная запись — `JournalEntry` (prototype-only структура)

Поля минимальной записи:

| Поле | Назначение | Обяз. |
|------|------------|:-----:|
| дата/время сделки | когда была сделка | да |
| инструмент | что торговал (текст, напр. «XAU/USD») | да |
| направление | покупка / продажа / наблюдение без входа | да |
| сетап / идея | на чём основано решение | нет |
| что планировал | намерение до сделки | нет |
| что сделал | фактическое исполнение | нет |
| вывод / урок | ключевой текст записи | да |
| ручной результат сделки | **необязательное** простое число | нет |
| `createdAt` / `updatedAt` | служебные метки | авто |

**Запрещено** добавлять в запись (канон приватности): `accountId`, `brokerId`, депозит, баланс,
процент доходности, импорт сделки, цену/объём/плечо как обязательные финансовые поля. Единственное
числовое финансовое поле — необязательный ручной результат **отдельной** сделки (см. §5).

## 4a. Второй инструмент — Risk Calculator (D4-C, реализовано)

Полное решение — **DD-314** (`DESIGN_DECISIONS.md`); состояния — `STATE_MATRIX.md` §5c; визуальный
отчёт — `docs/visual-reviews/D4_C_RISK_CALCULATOR.md`. Сводно:

- `tool.risk_calculator`, unlock **L15** через тот же канонический resolver; маршрут
  `/tools/tool.risk_calculator` на существующем `/tools/[toolCode]` (новой архитектуры нет);
- утверждённое направление **A+B**: Price Rail доминирует (входы слева · измеренный entry/stop Price
  Rail в центре · output-ledger справа), Direction B — только компактная sticky result-strip на mobile
  в valid-состоянии; не ticket/чек/broker order; на mobile нет submit/order-кнопки;
- четыре ручных входа: **Расчётный капитал** (временный вход расчёта, не баланс/счёт), **Риск на
  сделку, %**, **Цена входа**, **Стоп-цена**; вывод: **Сумма риска**, **Дистанция до стопа**, **Размер
  позиции**, **Расчётный номинал**; направление **Лонг/Шорт** (текстом, не только цветом);
- формулы: `riskAmount = capital × risk%/100`, `stopDistance = |entry − stop|`,
  `stopDistancePercent = stopDistance/entry × 100`, `positionUnits = riskAmount/stopDistance`,
  `positionNotional = positionUnits × entry`;
- чистая модель (`risk-calculation.ts` + `risk-format.ts`) без React/DOM/storage/fetch; контролируемый
  парсинг (`inputMode="decimal"`, `.`/`,`; знак/экспонента/пробелы/разрядные/смешанные разделители/
  non-finite отвергаются); дискриминированный incomplete/invalid/valid; fail-closed при overflow;
  RU-формат без научной нотации/`-0`/валютного символа;
- **без persist/fetch/XP/progression/journal/report write** — refresh сбрасывает все поля; ключа
  `ata.tools.risk-calculator` не существует; обязательный дисклеймер всегда виден;
- Tools Hub CTA стал per-tool (`ctaLabel`): «Открыть журнал» / «Открыть калькулятор»; featured
  инструмент = highest available (Risk L15 > Journal L10); поведение журнала не менялось;
- **вне scope D4-C:** история/persist калькулятора, другие tool internals, mentor, practical, backend.

## 5. Manual per-trade value — граница (критично)

Trading Journal может хранить введённый вручную результат **конкретной** сделки как простое
числовое значение. Это значение (DD-303):

- **не** является текущим балансом;
- **не** является балансом Pocket;
- **не** агрегируется в общий P/L;
- **не** используется для доходности или процентов;
- **не** используется как финансовый прогресс;
- **не** влияет на XP;
- **не** открывает уровни;
- **не** подтверждает checkpoint;
- **не** синхронизируется с брокером;
- **не** импортируется автоматически.

Правило представления: результат **визуально вторичен** по отношению к решению и выводу. Он —
метка на полях записи, а не заголовок. **Нет** итоговой строки, суммы, среднего, win/loss, процента
или графика. Отсутствие результата — нормальное, полноценное состояние записи (сделка-наблюдение
без входа).

Это прямое продолжение финансовой приватности ATA: продукт никогда не показывает баланс/депозиты/
выводы и не считает «осталось $X» (`CLAUDE.md`).

## 6. States

### 6.1 Tools Hub
- **has-unlocked** — есть открытые инструменты (канон для Артёма: Trading Journal + Risk
  Calculator открыты, дальше — locked previews). Основное состояние D4-A.
- **locked-preview (per tool)** — инструмент ещё не открыт: имя + «Откроется на уровне N», без CTA.
- *(будущее)* **empty / first-unlock** — только что открыт первый инструмент; вне D4-A.

### 6.2 Trading Journal
- **empty** — записей нет; видна точка добавления и честная подпись.
- **has-entries** — одна или несколько записей (канон D4-A: три записи — положительная,
  отрицательная, без денежного результата).
- **adding / editing entry** — открыта форма новой/существующей записи (встроена в поток, не
  административная анкета).
- **locked** — уровень инструмента ещё не достигнут (перехват до поверхности; переиспользует
  общий locked-explainer Tools).

Полная persistence/mutation-машина (autosave-состояния, диалоги, миграции хранилища) —
**вне D4-A**, проектируется в D4-B по образцу report-workspace.

## 7. Privacy boundary (сводно)

- Никакого баланса, депозита, вывода, «осталось $X», Pocket-CTA, суммарного P/L, win rate,
  доходности, equity curve, свечей/графиков, terminal-имитации.
- Единственное допустимое число — необязательный ручной результат отдельной сделки (§5),
  всегда вторичный и никогда не агрегируемый.
- Честная подпись про ручной ввод — обязательна на поверхности инструмента.

---

## 8. No-financial-aggregate rule

Ни одна поверхность Tools (hub или инструмент) **не** вычисляет и **не** показывает агрегат по
деньгам: ни сумму, ни среднее, ни счёт побед/поражений, ни процент, ни кривую. Любая сводка Tools
допускается только как **нефинансовая** (например «3 записи», «инструмент открыт на L10») —
количество и статус, но не деньги.

---

## 9. Locked tool previews

Locked-инструмент на hub:
- показывает имя инструмента (или нейтральный плейсхолдер, если раскрытие имени нежелательно —
  решается визуально в направлении) и подпись «Откроется на уровне N»;
- **не** имеет активной кнопки-действия и внутренней функциональности;
- геометрически отличается от открытого инструмента (приглушён), но остаётся частью того же Tools
  shell, а не отдельным «замком».

Минимум два locked-инструмента в D4-A: Chart Markup Tool (L20), Indicator Checklist (L25).

## 11. Future API boundary (описание, без реализации)

Когда появится backend (не в D4), поверхность Tools будет читать доступность инструментов из того
же progression-контракта, что и уровни, а записи Trading Journal — из browser-local store с
последующей опциональной серверной синхронизацией. Форма контракта (пример, **не** реализуется):

```
GET  tools            → [{ code, name, unlockLevel, state: "unlocked"|"locked" }]
GET  tools/{code}/entries        → JournalEntry[]        (browser-local в D4-B)
POST tools/{code}/entries        → JournalEntry
PATCH tools/{code}/entries/{id}  → JournalEntry
```

Никакой endpoint Tools не принимает и не возвращает баланс, депозит, агрегат P/L или broker-sync.
Ручной результат сделки остаётся полем отдельной записи и никуда не суммируется. Реализация
backend в D4 запрещена — это только граница на будущее.
