# Visual self-review — D3-C-B Revision Pass implementation

Проверялись реальные Chromium-кадры реализации (не прототипов): 14 first-pass кадров в
`design-memory/screenshots/d3-revision/first-pass/`, все просмотрены глазами; цвета review-кромок
дополнительно сняты computed-style'ом; геометрия (overflow, зазор CTA↔bottom-nav ≥12px на 390×844,
320×720, 720×450) закреплена behavioral E2E (`report-revision-smoke.spec.ts`), а не глазом — по
правилу DD-281.

## 1. Findings

### Critical

Не найдено. Все состояния цикла читаются, ни один контрол не перекрыт навигацией, все обязательные
тексты присутствуют и честны, raw section ID нигде не рендерятся, красного/percentage/stepper нет.

### Major

Не найдено. Отдельно проверены кандидаты:

- **кромка отмеченной секции** — подтверждено computed-style: `rgb(111 154 216)` =
  `--gate-boundary` (синяя review-семья), не зелёная D3-B; точка чипа «Нужна доработка» —
  полая (background transparent). Blue = review, green = сохранение/готовность/действие (DD-284);
- **feedback не конкурирует с работой** — полоса комментария и pass-строка занимают ~180px из 900,
  ледгер с открытой записью 3 остаётся доминирующим объектом кадра;
- **library/path** — статусы «Нужна доработка» / «Отчёт: Нужна доработка» на месте, CTA ведёт на
  чистый `/lessons/level.003`, уровень 4 без маршрута.

### Minor (зафиксированы, сознательно не правились)

- **m-1 (mobile 390).** Pass-строка переносится на две строки («Доработка 1 из 2 ·» / «дальше — …»)
  — перенос по словам, смысл и порядок сохранены; втискивание в одну строку потребовало бы мельче
  кегль.
- **m-2 (evidence).** В кадрах ready-* виден focus-ring на только что заполненном поле — артефакт
  способа съёмки (`fill()` оставляет фокус), в живом использовании это честный focus-visible.
- **m-3 (1440×900).** В pending-after-resubmit блок «Комментарий последней проверки» частично за
  фолдом — намеренно: это тихий контекст, а не активный список задач; конкурировать с pending-зоной
  он не должен.
- **m-4 (поведение).** Счётчик прохода остаётся «1 из 2» при правке первой отмеченной секции, пока
  вторая не посещена — по конструкции (проход считает просмотренные места, готовность к resubmit —
  отдельная строка); может прочитаться как «не засчитало». Наблюдение для будущих report-levels.
- **m-5 (mobile).** Заголовочная зона отмеченного «Итогового наблюдения» на 390px занимает три
  строки метаданных — читаемо, но плотно; при появлении новых пометок стоит пересмотреть порядок.

## 2. Соответствие выбранному направлению

- **B «Revision Pass»**: feedback — порядок работы; первая отмеченная секция открыта сразу; проход
  словами «Доработка 1 из 2 · дальше — Итоговое наблюдение» → «Доработка 2 из 2 · просмотрены —
  работа снова целиком ваша»; без процентов, колец, wizard-степперов.
- **Из A взяты ровно два элемента**: спокойная полоса «Комментарий проверки» над ледгером и
  человекочитаемые ссылки-переходы («Запись 03 · Что заметил после сделки», «Итоговое наблюдение»).
  Margin rail НЕ реализован.
- **Из C не взято ничего**: ни второго доминирующего объекта, ни правой плиты, ни дублированной
  closing zone — условия resubmit живут строкой у CTA и в диалоге подтверждения.
- **Коррекция относительно прототипа B выполнена**: обычные записи без «без пометок», не приглушены
  в недоступность (обычные `заполнена` + клик), отмеченные — со словесным состоянием.
